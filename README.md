# Система обліку видачі та повернення книг у бібліотеці

## Опис проєкту
Веб-застосунок для автоматизації обліку бібліотечного фонду: реєстрація книг, видача читачам, контроль повернення та строків.

## Основний функціонал
1. **Облік книг** — додавання, редагування та видалення книг у каталозі (назва, автор, рік, кількість екземплярів, статус: доступна/видана).
2. **Реєстрація читачів** — створення профілів читачів з базовими даними (ПІБ, контакти, номер читацького квитка).
3. **Видача та повернення книг** — фіксація факту видачі книги читачеві з датою видачі та плановою датою повернення, а також відмітка про фактичне повернення.
4. **Контроль прострочень** — автоматичне визначення книг, які не повернуто вчасно, зі списком боржників.
5. **Пошук і фільтрація** — пошук книг за назвою/автором та перегляд історії видач конкретного читача.

## Ролі (потенційні)
- **Бібліотекар (адміністратор)** — керує каталогом книг, оформлює видачу/повернення, керує обліковими записами читачів, бачить список боржників.
- **Читач** — переглядає каталог, свою історію видач та поточні книги на руках.

## Технології
React + Node.js + MongoDB

### Функціональні вимоги

| ID | Вимога | Пріоритет |
|---|---|---|
| FR-01 | Бібліотекар додає, редагує та видаляє книги в каталозі (назва, автор, рік, ISBN, кількість екземплярів); статус доступності обчислюється автоматично. | Must |
| FR-02 | Бібліотекар реєструє читачів; номер читацького квитка генерується автоматично та є унікальним. | Must |
| FR-03 | Бібліотекар оформлює видачу книги з датою видачі та плановою датою повернення (+14 днів); видача блокується за відсутності екземплярів, наявності прострочень або 5 книг на руках. | Must |
| FR-04 | Бібліотекар відмічає повернення; система фіксує фактичну дату, повертає екземпляр у фонд та обчислює дні прострочення. | Must |
| FR-05 | Система щоденно автоматично позначає прострочені видачі та формує список боржників із сортуванням за днями прострочення. | Must |

### Нефункціональні вимоги

| ID | Категорія | Вимога | Пріоритет |
|---|---|---|---|
| NFR-01 | Продуктивність | Відповідь на пошук у каталозі та список боржників ≤ 2 с при 10 000 книг і 50 одночасних користувачах. | Must |
| NFR-02 | Безпека | Автентифікація, паролі хешуються bcrypt, розмежування ролей (читач не має доступу до функцій бібліотекаря), HTTPS. | Must |
| NFR-03 | Надійність | Доступність ≥ 99 % у робочий час, щоденний бекап MongoDB, RPO 24 год, RTO 4 год. | Should |
| NFR-04 | Зручність використання | Видача книги — не більше 3 кроків і 60 с; інтерфейс українською; підтримка Chrome/Firefox/Safari та екранів від 360 px. | Should |
| NFR-05 | Супроводжуваність | REST API задокументовано в OpenAPI 3.0; покриття бізнес-логіки тестами ≥ 70 %; Node.js LTS. | Could |

### User stories (скорочено)

1. **US-01** — Як бібліотекар, я хочу оформляти видачу та повернення книг у системі, щоб не вести паперовий журнал і знати, у кого яка книга.
2. **US-02** — Як бібліотекар, я хочу бачити список боржників, щоб нагадувати про повернення та не втрачати книги з фонду.
3. **US-03** — Як читач, я хочу бачити свої книги на руках і строки повернення, щоб повертати їх вчасно.
4. **US-04** — Як бібліотекар, я хочу вести каталог книг, щоб він відповідав реальному фонду.
5. **US-05** — Як бібліотекар, я хочу реєструвати читачів, щоб оформлювати видачі лише зареєстрованим користувачам.
6. **US-06** — Як читач, я хочу шукати книги за назвою/автором, щоб не йти до бібліотеки марно.
